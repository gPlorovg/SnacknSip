# SnackNSip 🍿🥤

**SnackNSip** — сервис для выдачи еды и напитков на мероприятиях.
Проект состоит из Django API к которому есть интерфейс сайта и Telegram-бота.

---

## 📌 Mission

- Кто мы – мы онлайн сервис для заказа еды и напитков на мероприятиях;
- Что мы делаем - мы делаем заказ еды быстрым и легким и избавляем посетителей от ожидания в очередях;
- Для кого – для посетителей мероприятий, для их организаторов и вендоров, которые готовят еду;
- Ценность – наш продукт систематизирует и организовывает процесс обслуживания гостей мероприятиях.

## Vision

- К чему мы стремимся  - к ускорению и упрощению процесса заказа еды и напитков на мероприятии;
- Идеал - посетитель в пару кликов делает заказ, занимается активностями на мероприятии и за несколько минут забирает заказ, когда он будет готов;
- Изменение мира - на мероприятиях пропадают очереди к точкам с едой, люди вместо долгого ожидания наслаждаются мероприятием.

## 📂 Структура репозитория

```text
SnacknSip/

├── pyproject.toml / uv.lock   # Зависимости проекта (uv менеджер пакетов)

│   └── default.conf
├── src/                       # Основной Python / Django код

│   ├── config/                # Настройки проекта
│   │   ├── settings/          # Разделенные настройки (base.py, dev.py, prod.py)

│   └── apps/api/              # Ядро сервиса

└── ui/                        # Next.js веб-интерфейс
```

## 🛠 Требования к окружению

Перед запуском проекта убедитесь, что у вас установлены:
- **Python:** 3.12+
- **Менеджер пакетов:** [uv](https://github.com/astral-sh/uv) (рекомендуется для быстрой сборки и управления зависимостями)
- **Инфраструктура:** Docker & Docker Compose V2

## 🚀 Инструкция по запуску

### 1. Локальная разработка (Dev-режим)
В режиме разработки инфраструктура (БД, Кеш, S3) поднимается в Docker, а сам Django-вебсервер запускается локально.

```bash
# 1. Клонирование репозитория
git clone https://.../SnacknSip.git
cd SnacknSip

# 2. Установка зависимостей через uv
uv sync

# 3. Настройка окружения
cp .env.example .env

# 4. Запуск инфраструктурных контейнеров
docker compose up -d

# 5. Применение миграций БД
cd src
python manage.py migrate

# 6. Запуск локального сервера
python manage.py runserver
```

> **Справка для разработчиков:**
> Swagger документация API по умолчанию будет доступна по адресу `http://localhost:8000/api/docs/`

### 2. Запуск тестов
Проект покрыт unit и интеграционными тестами (`pytest`).

```bash
cd src
# Запуск всех тестов в проекте с подробным логированием:
pytest apps/api/tests/ -v
```

### 3. Продакшен запуск (Docker)
Продакшен включает в себя Gunicorn (backend), отдельный Next.js контейнер (frontend), Nginx как единый reverse proxy, фоновые воркеры Celery.

```bash
# 1. Создание актуального env-файла для продакшена
cp .env.prod.example .env.prod
# Отредактируйте .env.prod (укажите пароли, POSTGRES_DB и т.д.)

# 2. Билд и запуск (используя docker-compose.prod.yml)
docker compose --env-file .env.prod -f docker-compose.prod.yml up --build -d
```

После запуска:
- `http://<домен>/` -> веб-интерфейс из `ui/`
- `http://<домен>/api/` и `http://<домен>/admin/` -> Django backend

## 🚨 Возможные ошибки и их решения

#### 1. `django.db.utils.OperationalError: could not translate host name "db" to address` (или `Connection Refused` к PostgreSQL)
**Причина:** Вы пытаетесь запустить `python manage.py runserver` напрямую, пока Docker-контейнер с базой данных `db` еще выключен. Либо неправильно настроены переменные окружения в `.env` файле.
**Решение:**
1. Проверьте, поднят ли локальный Docker-контейнер: `docker compose up -d`
2. Убедитесь, что в локальном `.env` стоит `DB_HOST=localhost` (тогда как в `.env.prod` прописано `DB_HOST=db`).

#### 2. `PermissionError: [Errno 13] Permission denied: '/app/staticfiles'`
**Причина:** При запуске в Prod через Docker, пользователю `appuser` (под которым работает приложение) не хватает прав на запись в примонтированный volume со статикой. Скрипт `entrypoint.sh` не может выполнить `collectstatic`.
**Решение:** Удалите старые Volume системной базы и статики командой `docker compose -f docker-compose.prod.yml down -v` и запустите билд заново. Новый `Dockerfile` сам создаст нужные директории с правильными `chown`:
```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up --build -d
```

#### 3. Pytest: Ошибки Integrity Error или связанные с уникальностью
**Причина:** Локальные тесты могут падать, если в них вручную "хардкодятся" одни и те же `ID`, либо создаются объекты-дубликаты (например, один и тот же `MenuItem` внутри одной точки).
**Решение:** Всегда используйте написанные нами фабрики (`factory_boy` -> `factories.py`), которые автоматически генерируют корректные и рандомизированные связи, не допуская конфликтов в БД.

#### 4. Не работает авторизация в Swagger API Docs (No response body)
**Причина:** Если Swagger не выводит ответ на определенную ручку, возможно, вы забыли передать токен авторизации или же ответ не был задокументирован декоратором `responses={}`.
**Универсальное решение в Swagger:** Кликните `Try it out` на POST `/api/auth/login/`, получите `access` токен (JWT), нажмите кнопку `Authorize` в самом верху страницы и вставьте его туда в формате _**Bearer <ваш_токен>**_. Это разблокирует все остальные ручки.
